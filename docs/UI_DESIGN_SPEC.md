# LabelPilot UI 设计规范（Draft）

> 版本：0.3（规则、实现状态与复用建议分离）  
> 状态：Draft，尚未纳入发布流程。  
> 适用范围：LabelPilot Web/PWA 的界面视觉、交互、响应式和无障碍契约。  
> 最后核对：2026-09-19（源码、测试及 Chromium 360px 移动流程；非全界面浏览器验收）。  
> 本文不规定 PDF 排版算法、图片校验规则或持久化数据结构。

## 0. 使用方式与规范级别

本文使用以下规范词：

- **MUST（必须）**：属于可访问性、布局不变量、状态反馈或已有测试契约，改动时必须同步更新实现与测试。
- **SHOULD（应）**：默认设计选择。确有产品理由时可以偏离，但要在代码附近或本文的“决策与例外”中说明。
- **MAY（可以）**：实现自由度，不构成视觉一致性要求。

### 0.1 来源优先级

用户确认的产品与设计决定约束实现；源码和测试用来核实落实情况，不能自动把现有缺陷变成设计标准。本文仍为 Draft，新增候选方案不代表已经批准或完成重构。

- **设计要求**：正文中的“必须/应”描述目标，不宣称已全部满足。
- **当前实现**：明确标注的尺寸、代码模式和来源，是核对时的实现快照。
- **待落实/待验证**：集中记录在第 12 节，修订文档不会自动消除实现差距。
- **提取建议**：第 7.5 节是后续重构候选，不要求一次性实施。

冲突时先判断是实现缺陷还是有意变更，再同步修订受影响的规则、代码和测试。截图辅助审美验收，浏览器测量验证布局和命中区；class 断言只能证明结构意图。

### 0.2 术语

- **CSS 盒尺寸**：控件布局计算出的宽高；可能受缩放影响，也可能被父容器裁剪。
- **可见尺寸**：经过缩放、裁剪后用户实际看到的范围，不能仅由 CSS 高度推断。
- **命中区**：用户实际可以点击或触摸的范围，可通过 `hit-target` 扩展，不等于视觉尺寸。
- **移动布局**：`lg` 以下，即 `<1024px`；编辑入口由 `MobileActionBar` 打开 `EditSheet`。
- **桌面布局**：`lg` 及以上，即 `≥1024px`；显示固定宽度的 `ControlPanel`。
- **表面**：`background`、`surface`、`elevated` 三类层级，而不是任意新增背景色。

## 1. 设计方向

LabelPilot 是一个“精密工具工作台”：纸张预览是主角，控制区服务于快速排版和输出。

设计应遵循以下原则：

1. **预览优先**：左侧/底部设置服务于右侧纸张预览，不用装饰性卡片抢占首屏。
2. **密集但可读**：减少重复状态和无效留白，但不压缩标签、输入和触控目标。
3. **语义优先**：蓝色表达品牌主操作和当前选择；弱化文字、边框和表面只承担层级，不承担业务状态。
4. **可见尺寸与命中区分离**：图标可以保持克制，触控区域通过 `hit-target` 扩展。
5. **状态明确**：hover、active、focus、disabled、生成中、成功和失败都应有稳定且可预测的表现。

## 2. 页面结构与响应式

### 2.1 桌面布局

- `lg` 及以上显示桌面控制面板和弹性预览区。
- 控制面板基准宽度为 `20rem`（`lg:w-80`）。
- 预览区占据剩余空间，纸张、网格和缩放控件保持视觉主角地位。
- 控制面板内部使用 `min-h-0 flex-1` 和 `lg:overflow-y-auto`，生成按钮固定在底部。

### 2.2 移动布局

- `lg` 以下隐藏桌面控制面板，使用预览区、底部操作栏和 `EditSheet`。
- 编辑面板默认约占 `62dvh`，可切换为全屏；正文滚动，底部安全区单独处理。
- 移动端不能简单地把桌面控件缩小；应保留可读的视觉尺寸和足够的触控命中区。
- 使用 `env(safe-area-inset-*)` 时，避免根容器与底部面板重复叠加安全区。

### 2.3 断点与尺寸矩阵

项目只把 `lg` 作为主要布局断点；`sm` 只用于头部品牌字标、设置浮层和更新提示的空间优化。

| 视口范围          | 头部                                       | 主布局                                        | 编辑/输出操作                  | 重点验收                                          |
| ----------------- | ------------------------------------------ | --------------------------------------------- | ------------------------------ | ------------------------------------------------- |
| `<640px`          | 只显示 Logo 图标，保留语言、主题和设置入口 | 预览区占满剩余高度                            | 底部操作栏 + `EditSheet`       | 320px 内容宽度不横向溢出，底部安全区可见          |
| `640–1023px`      | 显示 Logo 与 `LabelPilot` 字标             | 仍使用移动布局                                | 底部操作栏 + `EditSheet`       | 长文件名、表单和 Toast 不挤压主操作               |
| `≥1024px`（`lg`） | 完整桌面头部                               | `ControlPanel` 固定 `20rem`，预览区占剩余空间 | 生成按钮固定在桌面控制面板底部 | 1280×720 和低高度窗口可滚动，生成按钮不被内容覆盖 |

应用根容器使用 `h-dvh`；页面主区使用 `min-h-0`，避免 flex 子项把滚动责任推给 `body`。桌面主区为 `p-3`、`gap-3`，移动主区为 `p-2`、`gap-3`；这些值属于当前布局基线，不应在单个组件中随意改成相邻的任意值。

### 2.4 溢出与滚动规则

- 只有明确的内容滚动容器负责滚动，不能依赖外层 `fieldset` 或普通 `div` 的偶然高度。
- 长文件名、Toast、设置项和状态文案优先使用 `min-w-0`、`truncate` 或 `break-words`，不能横向撑破面板。
- 重要内容不可只靠 hover 才能发现。
- 桌面控制面板的滚动链必须是：`aside` → `fieldset.flex.flex-col` → 内层 `min-h-0 flex-1 lg:overflow-y-auto`；底部生成区不在滚动容器内。
- `EditSheet` 的滚动链必须是：面板固定高度 → `min-h-0 flex-1 overflow-y-auto`；面板头部和“查看预览”按钮保持可达。
- 预览纸张允许在自己的容器内平移和缩放；不能因为纸张尺寸把应用根容器撑出横向滚动条。

### 2.5 层级与浮层

z-index 是界面层级契约。新增浮层应先归入现有层级，不要临时发明更大的数值。

| 层级       | 当前实现               | 责任                                                    |
| ---------- | ---------------------- | ------------------------------------------------------- |
| 基础内容   | `z-0` / 无显式层级     | 表单、纸张和普通卡片                                    |
| 控制叠加   | `z-10`、`z-20`、`z-30` | 上传 input 覆盖层、预览标尺、缩放/分页控制、头部        |
| 对话框层   | `z-50`                 | `EditSheet`、`SettingsMenu`、`CalibrationDialog`、Toast |
| 浮层子菜单 | `z-[100]`              | 设置菜单中的纸张预设列表                                |
| 更新提示   | `z-[1000]`             | PWA 更新/离线提示，必须始终可发现                       |

以上是实现快照，不是全局层级已验收的声明。z-index 只能在相应 stacking context 内比较，设置菜单的局部 100 不一定高于根级 50。新增浮层应检查祖先定位、transform 和层叠上下文；更新提示的 1000 也不应成为任意覆盖模态操作的理由。

## 3. 颜色与表面

颜色必须优先使用 `src/index.css` 中的语义 token，不直接在组件中重复定义亮色/暗色具体灰阶。

| 语义          | 当前 token      | 用途                         |
| ------------- | --------------- | ---------------------------- |
| 页面背景      | `background`    | 工作台最外层                 |
| 普通面板      | `surface`       | 控制面板、表单区域           |
| 浮层/抬升表面 | `elevated`      | 设置、Toast、分页和缩放控件  |
| 主文字        | `text-main`     | 标题、文件名、主要数值       |
| 弱化文字      | `text-muted`    | 辅助说明、文件大小、次要图标 |
| 细边框        | `border-subtle` | 面板、输入框、分隔线         |
| 品牌主色      | `brand-primary` | 当前选择、主操作、链接性反馈 |
| 品牌前景      | `on-brand`      | 品牌色按钮上的文字/图标      |

规则：

- 亮色和暗色只通过主题 token 改变，不在组件中复制 `dark:*` 灰阶组合。
- 普通面板与浮层要有可感知但克制的层级差；不要用厚边框、渐变或玻璃拟态制造层级。
- 纸张预览中的白色、黑色和 Courier 文本属于输出预览语义，不强行替换成 UI token。
- 红色、琥珀色、绿色只用于错误、警告、成功等明确状态。

### 3.1 当前主题值

下表记录当前实现中的主题引用。zinc 色值由已安装 Tailwind 定义，避免把近似十六进制值当成独立真相；组件仍引用语义 token。

| 语义 token      | 亮色       | 暗色       | 说明                      |
| --------------- | ---------- | ---------- | ------------------------- |
| `background`    | `zinc-100` | `zinc-950` | 应用工作台底色            |
| `surface`       | `zinc-50`  | `zinc-900` | 普通面板、输入区域        |
| `elevated`      | `#ffffff`  | `zinc-800` | 浮层、Toast、控件容器     |
| `text-main`     | `zinc-800` | `zinc-200` | 主标题、文件名、数值      |
| `text-muted`    | `zinc-600` | `zinc-400` | label、辅助说明、弱化图标 |
| `border-subtle` | `zinc-200` | `zinc-800` | 细边框与分隔线            |
| `brand-primary` | `#0369a1`  | `#38bdf8`  | 主操作、选中和焦点        |
| `on-brand`      | `#ffffff`  | `#082f49`  | 品牌主色上的前景          |

品牌色与前景色的组合必须保持 WCAG AA 普通文字对比度（当前测试阈值为 `4.5:1`）。刻度尺使用 `--calibration-ruler-tick` 和 `--calibration-ruler-minor-tick`，不可用固定黑色覆盖暗色主题。半透明叠加（例如 `bg-brand-primary/10`）只用于背景提示，不替代错误、警告和成功的文字语义。

## 4. 字体与文字层级

- UI 无衬线字体使用 MiSans，并保留系统中文/英文回退字体。
- 数字、毫米、百分比、数量和校准值优先使用 Maple Mono 等宽字体。
- PDF/纸张预览中的 ASCII 输出继续使用 Courier，以保持所见即所得的一致性。

建议层级：

| 用途              | 规则                                                   |
| ----------------- | ------------------------------------------------------ |
| 分组标题          | `group-title`，通常 `text-xs`、`font-semibold`、弱化色 |
| 字段 label        | `text-sm font-medium text-text-muted`                  |
| 正文/文件名       | `text-sm`；文件名可用 `font-semibold` 强调识别         |
| 辅助说明/文件大小 | `text-xs text-text-muted`                              |
| 主按钮            | `text-sm font-bold`                                    |
| 数值输入          | `font-mono text-sm font-semibold`                      |

中文环境只保留轻微字距，不使用英文大写标题的宽 tracking 逻辑强行处理中文。

### 4.1 文本行为

- 标签和按钮文案优先使用短动词或当前动作，避免把帮助说明塞进主按钮。
- 文件名、纸张信息和状态值必须允许收缩；在 flex 行中同时使用 `min-w-0` 与 `truncate`，完整值通过 `title` 或可访问名称保留。
- 错误和警告不能只依靠红/琥珀颜色；至少提供可读文字，并让屏幕阅读器通过 `role="alert"` 或关联描述获得信息。
- 等宽字体只用于数字、单位、校准值、前缀和可复制的技术字符串；普通中文说明继续使用 MiSans。

## 5. 间距、圆角与边框

优先复用 Tailwind 现有尺度，避免为单个控件发明新的间距值。

- 常用横向间距：`gap-1.5`、`gap-2`、`gap-3`、`gap-4`。
- 常用纵向节奏：`space-y-2`、`space-y-3`、`space-y-4`、`space-y-5`。
- 普通控件：`rounded-md`。
- 面板和较大容器：`rounded-lg`。
- 移动端底部面板或明确的区域卡片：可使用 `rounded-xl`。
- 只有胶囊、状态标记和滑块等有语义需要时使用 `rounded-full`。
- 普通面板使用 1px `border-border-subtle`；阴影只用于浮层和主要抬升表面。
- 同一个控件内部必须遵循同心圆角关系，内部圆角不能大于外部圆角。

### 5.1 尺度与盒模型

Tailwind 间距以 `0.25rem = 4px` 为基准：`1.5=6px`、`2=8px`、`3=12px`、`4=16px`、`5=20px`。当前常用圆角为 `rounded-md=6px`、`rounded-lg=8px`、`rounded-xl=12px`、`rounded-2xl=16px`。

在默认根字号 16px、无额外内边距时，`border-box` 下带上下各 1px 边框的 `h-10` 容器内容盒为 38px。普通流中的 `h-full` 子项可能据此得到 38px；绝对定位等情况须按实际包含块核对。

图片数量复合框使用不占布局尺寸的 inset shadow 表达边框，内部按钮显式使用 `h-10`；Chromium 360px 流程确认外框和按钮均为 40px 高，焦点轮廓位于控件内部而不被 `overflow-hidden` 裁掉。这是复合控件的实现方式，不应把“给内部盒子增高”当成通用修复模板。

普通边框统一通过 `input-base` 或 `border border-border-subtle` 表达；不要同时叠加多个相同语义的 border、ring 和 shadow，除非它们分别承担聚焦与层级职责。

## 6. 控件尺寸与命中区

### 6.1 可见尺寸

| 控件类型       | 建议可见尺寸 | 典型实现                    |
| -------------- | ------------ | --------------------------- |
| 次要图标操作   | 32×32px      | `h-8 w-8` + `hit-target`    |
| 紧凑导航操作   | 36×36px      | `h-9 w-9` + `hit-target`    |
| 移动端表单控件 | 40px 高      | `h-10`，步进按钮通常 `w-10` |
| 移动端主要操作 | 至少 44px 高 | `h-11` 或等效内边距         |

### 6.2 命中区

`hit-target::after` 默认四边各扩展 6px；`IconButton` 会按可见尺寸及是否带边框覆盖 `--hit-target-inset`，带边框 tone 额外补偿 1px padding-box 差异，使 22/24/32/36px 变体的理论命中范围均达到 44px。实际命中还受裁剪、相邻覆盖和 pointer-events 影响。44px 是项目的触控设计目标；现有 40px 步进控件属于紧凑尺寸选择，不宣称已满足全部触控目标。

- 使用 `hit-target` 时，不要同时把所有次要图标按钮都做成可见 44×44px，否则会造成视觉拥挤。
- 相邻命中区应互不重叠；可见边缘间距至少为两侧实际扩展量之和。排序按钮仍使用默认 6px 扩展，因此采用 `gap-3`（12px）；其他组合按自身尺寸和变量计算，不能固定套用一个间距。
- Toast 的 22px 关闭按钮向外扩展 11px，前方 `gap-3` 为 12px；Chromium 命中测试确认扩展区只占用间隙、不覆盖消息文字。Zoom 的 reset 为 32px + 6px 扩展，桌面 `1:1` 为 36px + 4px 扩展，两者使用 10px 间距，命中区相接但不重叠。
- 触控反馈使用 `active:*`；hover 只作为支持 hover 设备的增强反馈。
- 键盘焦点使用全局 `focus-visible` 轮廓，不得通过 `outline-none` 抹掉而没有替代方案。

### 6.3 输入和步进器

- 标准输入使用 `input-base`，聚焦时使用 `input-base-focus`。
- `NumberInput` 和图片数量控件在移动端采用相同的 40px 视觉高度、等宽步进按钮和 16px Lucide 图标。
- 到达最小值/最大值时，步进按钮应禁用、降低对比度并取消 hover 反馈。
- 输入草稿可以暂存中间态，但失焦、Enter、Escape 的行为必须明确且可测试。

`NumberInput` 和 `ThumbnailItem` 数量按钮均在数值边界使用原生 `disabled`；调用方仍须保留数值归一化作为业务防线。公共步进按钮和图标按钮的 hover 样式必须使用 `enabled:hover:*`，不能让禁用控件仅因指针经过而变色。

## 7. 组件模式

### 7.1 分段控件

`SegmentedControl` 用于同级模式或方向选择：

- 外层使用轻微背景、细边框和 `rounded-lg`。
- 内部按钮使用同心的 `rounded-md` 和至少 `min-h-10`。
- 当前项使用 `aria-pressed`，品牌色表达当前选择，不额外使用第二套强调色。

### 7.2 图片队列

`ThumbnailItem` 是可操作列表行，不是装饰性缩略图网格：

- 第一行优先保证拖拽把手、缩略图、可见文件名和删除操作。
- 第二行承载数量、上下移和文件大小。
- 文件名必须可见；长名称允许截断，但通过 `title` 保留完整内容。
- 删除按钮在触摸设备上持续可发现，不能只依赖 hover。
- 排序既支持拖拽把手，也支持带有清晰无障碍名称的上下移按钮。
- 已有图片时，上传入口应收缩为“继续添加图片”，不重复显示“已选择 N 张图片”。

### 7.3 主要操作按钮

`SmartButton` 是页面唯一的主要生成操作：

- 可用、禁用、生成中、成功和失败必须在同一个操作表面内表达。
- 生成中保留取消入口；取消不应被输入锁定逻辑禁用。
- 进度状态需要同时提供可见文案和 `aria-live` 状态。

### 7.4 浮层、抽屉和提示

- 对话框使用 `role="dialog"`、标题关联、Escape 关闭、Tab 环回和关闭后焦点恢复。
- 设置菜单属于轻量浮层；背景操作、外部点击和焦点恢复行为要与其语义一致。
- Toast、PWA 更新提示和错误页复用 `elevated` 表面，不使用组件私有白色/黑色背景。

### 7.5 公共组件提取原则

公共组件的目标是让同一契约只有一个视觉实现，而不是把所有相似 JSX 合并成一个“万能组件”。满足以下条件时才抽取：

1. 至少有两个真实调用点；
2. 视觉结构、键盘行为、无障碍语义和状态模型基本一致；
3. 抽取后能减少重复 class 和重复测试，而不是增加大量互斥 props；
4. 业务校验、文案和数据变换仍由调用方负责，公共组件只拥有明确的 UI 契约。

建议按以下优先级演进：

| 优先级     | 候选                              | 当前调用点/范围                                                     | 建议边界                                                                                  | 不应合并的部分                                            |
| ---------- | --------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| P0 已落地  | `StepperButton`                   | `NumberInput`、`ThumbnailItem`                                      | 统一 `40px` 移动端步进按钮、图标、禁用/焦点/按压状态和 aria 命名；支持水平/响应式布局变体 | 行列/毫米的数值解析、图片数量草稿与业务上限               |
| P1         | `FieldShell`                      | `NumberInput`、文本前缀、校准输入、设置输入                         | 管理 label、hint、error 与输入的 ID 关联，统一字段间距                                    | 数值解析、校验时机和文案；仅封装 `useId` 的 hook 收益不足 |
| P1         | `InlineAlert`                     | 生成就绪错误、文本错误、校准普通错误                                | 首版只统一 danger tone、文字对比度和 `role`；有第二个 boxed 场景后再扩展形态              | Toast 的定位、生命周期、关闭动作和 live region 保持独立   |
| P0 已落地  | `useModalFocus`                   | `EditSheet`、`CalibrationDialog`                                    | 统一首焦点、Escape、Tab 环回和关闭后焦点恢复；过滤不可聚焦项                              | `SettingsMenu` 背景可点击，仍单独处理 popover/dialog 语义 |
| P0 已落地  | `IconButton`                      | Header 主题、Zoom reset、PageNavigator、Toast/ReloadPrompt 关闭按钮 | 统一有限尺寸变体、图标对齐、焦点和禁用反馈；提供明确名称，支持 ref 和原生事件             | 带文本按钮、生成状态机；拖拽把手和列表排序/删除暂未迁移   |
| P1         | `ActionButton`                    | 校准保存/取消、查看预览、更新提示、错误页操作                       | 原生属性/ref + 少量 primary/secondary/quiet 变体，统一按压、焦点和禁用状态                | `SmartButton` 的生成/取消状态机                           |
| 已有待深化 | `SegmentedControl`、`SmartButton` | 模式/方向切换、桌面与移动生成入口                                   | `SegmentedControl` 内部生成唯一 layout ID，并评估校准参考长度的第 4 个调用点              | 不在调用方复制一套近似 class                              |

P0/P1 表示复用收益优先级，不代表生产故障等级。“已落地”只表示首批调用点已经迁移，不代表所有相似按钮都必须立刻迁移。

### 7.6 提取范围与迁移约束

- **步进按钮先于整个数值输入**：`NumberInput` 在桌面是竖排箭头，移动端是横排加减；图片数量一直是横排。先共享按钮 Module，通过少量布局变体统一图标与尺寸，保留各自草稿提交和归一化行为。调用方提供已翻译名称、disabled 和事件；公共 Module 不导入 store 或业务上限。
- **IconButton 的 Interface**：有限的 size/tone、必需的可访问名称，加原生 button 属性/ref。内部统一图标尺寸、默认 `type="button"`、focus-visible 和 disabled；不让每个调用点继续覆盖宽高。不默认给所有按钮套 `hit-target`，由布局决定不重叠的命中策略。
- **字段容器与输入样式分工**：`FieldShell` 负责 label/hint/error 关联；基础输入外观继续复用 `input-base`。只包一层 input 并透传全部 class 的 Module 收益有限，暂不另建。
- **提示语义由使用场景决定**：普通行内错误可以共享窄范围的 danger tone；Toast 和更新提示只共享状态色 token，不共享布局、生命周期、关闭动作或 live region。避免提示内部和外层同时建立 live region，造成重复播报。
- **普通文字按钮可独立演进**：校准保存/取消、查看预览、更新按钮存在颜色与禁用样式重复，可直接评估少量 primary/secondary/quiet 变体，不依赖 IconButton；`SmartButton` 的生成/取消状态机保持独立。
- **模态焦点与轻量浮层分开**：`EditSheet` 和 `CalibrationDialog` 已共享 `useModalFocus`，由模块统一首焦点、Escape、Tab 环回、关闭恢复和不可聚焦项过滤；`SettingsMenu` 允许背景点击，仍不纳入这个真正模态的默认策略。
- **状态色和表面优先用 token/utility**：danger、warning、success 的前景/淡背景/边框可以集中；重复的 `border + bg-surface` 可评估 `surface-card` utility，不为此创建透传大量布局参数的 React `Surface`。
- **分组标题先保留 utility**：`LayoutFields`、`TextModeFields`、图片分组共享 `group-title` 已有收益。仅标题加图标不必立即建组件；如需统一帮助入口或右侧摘要，再提取 SectionHeader，并允许调用方指定 h2/h3。
- **暂不提取**：二维码开关仅一个使用场景；QR 原生 range 与预览竖向缩放条交互不同；上传入口有真实文件 input 覆盖层，不能直接替换成普通按钮；预设菜单和分段选择的键盘语义也不同。
- **继续复用已有模块**：`LayoutFields`、`TextModeFields`、`ImageFilesSection`、`SegmentedControl`、`SmartButton` 已在桌面/移动流程复用，不再创建两套近似实现。

共享视觉 Module 可放在 `src/components/ui/`，业务组合留在现有目录；这是迁移建议，不为整理目录而移动无关文件。遵循 codebase-design 的小 Interface 原则：调用方只描述意图，尺寸、状态和关联复杂度集中在 Implementation；若移除 Module 后复杂度没有重新散落到调用点，就应重新评估提取价值。

每次先迁移两个真实调用点，通过行为测试和浏览器样式检查，再扩展。验证重点是键盘操作、disabled 不触发、aria 关联、亮暗主题、窄宽度和真实点击范围；不以 class 字符串一致作为唯一验收。视觉快照可逐步建立，不作为所有提取工作的前置工程。

## 8. 状态与无障碍

- 每个图标按钮必须有可翻译的 `aria-label`；纯装饰图标使用 `aria-hidden`。
- 可见文字与无障碍标签可以不同，但必须表达同一动作；例如紧凑上传入口可显示“继续添加图片”，文件 input 仍保留完整标签。
- 禁用状态必须使用原生 `disabled`，并提供明确的低对比视觉；不能仅靠颜色区分。
- 错误信息使用 `role="alert"`，输入关联错误时使用 `aria-describedby`。
- 弹窗和抽屉打开后，焦点进入当前容器；关闭后回到触发控件。
- 不把 hover 作为触摸或键盘用户发现操作的唯一途径。
- 当前主题测试仅数值验证两组品牌背景/前景组合，并检查刻度 token 引用；普通文字、半透明状态色和完整界面的对比度仍需验证。

### 8.1 状态矩阵

| 状态           | 视觉要求                                                  | 行为要求                                                           |
| -------------- | --------------------------------------------------------- | ------------------------------------------------------------------ |
| 默认           | 使用语义表面、文字和边框 token                            | 可操作控件必须有明确名称和可见目的                                 |
| Hover          | 只在支持 hover 的设备上增强背景/边框/文字                 | 不能是发现操作的唯一方式；不要造成布局位移                         |
| Active/Pressed | 使用 `active:*` 或等效按压反馈                            | 触摸操作要有即时反馈；不改变业务值以外的布局                       |
| Focus-visible  | 全局 `2px` 品牌色 outline，`2px` offset                   | 不用 `outline-none` 隐藏键盘焦点，除非有等价且可见的替代样式       |
| Disabled       | 原生 `disabled`、低对比度、`cursor-not-allowed`（适用时） | 不响应点击、键盘、拖拽或 hover/active 反馈；不能只靠透明度判断原因 |
| Generating     | 主要输入由 `fieldset[disabled]` 冻结，生成按钮变为取消    | 取消操作必须保持可用；进度同时有可见文案和 `aria-live`             |
| Success/Error  | 使用明确的绿色/红色表面并配图标和文字                     | 状态不能只由颜色表达；应按流程自动恢复或提供下一步                 |

### 8.2 组件语义契约

- `SegmentedControl` 使用 `role="group"` + `aria-pressed`；不要用普通链接模拟互斥选择。
- QR 开关使用 `role="switch"` + `aria-checked`；滑块必须提供 `role="slider"`、范围和当前值。
- 图片列表的拖拽把手、上移/下移和删除必须分别可聚焦、可翻译命名；拖拽不是键盘排序的唯一入口。
- `EditSheet` 和 `CalibrationDialog` 当前声明 `role="dialog" aria-modal="true"`，有遮罩、首焦点和 Tab 环回逻辑。模态验收还需检查隐藏/禁用控件过滤、背景不可操作和辅助技术行为，不能仅由 aria 声明判定完整合规；校准对话框首焦点当前为测量输入。
- `SettingsMenu` 当前也使用 dialog 语义、Tab 环回和 Escape；它仍允许鼠标点击背景，因此这是现有兼容例外，不应复制到新的轻量 popover。若改成真正 popover，必须同步修改 `role`、背景交互和测试。
- 错误提示使用 `role="alert"`；字段错误通过 `aria-describedby` 和 `aria-invalid` 关联到输入。

## 9. 动效

- 高频控件只使用颜色、透明度或轻微按压反馈，不做明显位移或弹跳。
- 浮层、Toast、抽屉和列表进入动画通常使用 150–200ms `ease-out`。
- 不使用 `transition-all`；明确列出需要动画的属性。
- 必须遵守 `prefers-reduced-motion`，减少或移除非必要动画。

当前动效基线：

| 场景                | 时长/曲线          | 规则                                                          |
| ------------------- | ------------------ | ------------------------------------------------------------- |
| 输入边框、按钮颜色  | `150ms` 左右       | 只过渡 `border-color`、`background-color`、`color` 等明确属性 |
| Toast、抽屉、对话框 | `180ms ease-out`   | 允许透明度、位移或轻微缩放；不动画化高度                      |
| 列表项进入          | `150ms ease-out`   | 保持列表顺序和可操作性稳定                                    |
| 生成状态与进度      | `200ms` 或线性进度 | 状态切换优先于装饰性过渡                                      |
| 主题切换            | 基础层约 `300ms`   | 只过渡颜色相关属性，不阻塞交互                                |

`prefers-reduced-motion: reduce` 下，CSS 会把动画/过渡压缩到近乎零并关闭平滑滚动；新增 Framer Motion 动画也必须继承这一意图，不得只依赖 CSS 覆盖。

## 10. 文案与国际化

- 文案优先说明“用户现在能做什么”，避免重复展示同一状态。
- 上传后文件卡片已经表达文件数量，上传区域只保留继续添加的动作。
- 中英文都要通过 `translations.ts` 提供，不在组件中硬编码用户可见文案。
- 中文短标题不套用英文大写语法；按钮文案保持短、直接、可扫描。

### 10.1 文案验收

- 同一动作在桌面和移动端使用同一翻译 key，允许根据空间使用不同布局而不改变语义。
- 文件名、数量、单位和百分比由格式化函数或翻译参数生成，不手拼不同语言的标点顺序。
- `aria-label`、`title`、可见按钮文字和错误提示都属于用户可见文案，必须一并进入翻译资源审查。
- 新增文案至少核对中文、英文、长文件名和 320px 内容宽度；不得用截断掩盖动作含义。

## 13. 决策与例外记录

以下决定已经反映在当前实现中，后续改动不应无意回退：

1. **图片上传摘要精简**：没有图片时显示完整上传引导；已有图片时只显示“继续添加图片”，文件卡片承担数量和文件识别信息。
2. **图片队列两行布局**：第一行优先保证拖拽、缩略图、文件名和删除；第二行承载数量、上下移和文件大小，排序按钮不再挤占文件名宽度。
3. **40px 步进控件基线**：移动端数量控件维持紧凑视觉；现有 40px 尺寸断言应保留，重构还须补可见裁剪、焦点和命中区验证，不能把某组 class 当成唯一实现。
4. **桌面滚动链**：`ControlPanel` 的 `fieldset` 必须是 flex 列，滚动属性属于明确的内层滚动区；生成按钮位于滚动区之外。
5. **错误可见性**：图片累计数量错误位于可折叠文件区之外，文件区折叠后仍须可见。
6. **移动与桌面分工**：`lg` 以下只保留预览、底部操作栏和编辑面板；进入桌面断点时清理旧的移动面板状态。

这些记录是当前产品行为的 UI 约束，不等于永久不可改变；改变时必须在同一提交中更新实现、测试和本文。
